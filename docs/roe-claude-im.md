## Non-negotiable working rules (Abi-locked)

1. **Understand the app first.** Purpose and existing behavior beat clever new structure.
2. **Do not make assumptions.** Verify in code, docs, Firestore shapes, and DECISIONS (when present). If unsure, ask Abi or Cos — do not silently invent.
3. **Keep naming conventions.** Match existing paths, collection names, axis vocabulary, file kebab-case in `docs/`, and established identifiers. Do not introduce alternate spellings for the same concept.
4. **Do not create things already in place.** Search the repo before adding collections, helpers, gateways, confirm flows, or docs. Extend or reuse.
5. **Any change must be fully informed.** Before editing: read the relevant code and docs; know the blast radius (UI, Cloud Functions, Firestore rules, bots, deploy). Prefer the smallest change that solves the problem.

## Locked product decisions (do not relitigate)

- **Keep `bot_gateway`.** Live FA HTTP path. Complementary to `functions/finance.py` / finance chat aggregates (not a second write stack to drop). Later cleanup may rename “Chief of Staff” comments toward Advisor / axis-chief reads (DECISIONS 2026-09-14) — that is not a reason to remove the gateway.
- **`axisProposals` stays separate** from `botGatewayConfirmations`. Finance confirms are hash-pinned with a short TTL (pending / consumed / expired). Weekly axis proposals need long-lived states (open / taken / passed). Reuse the **dispatcher shape** of `resolve_confirmation` if useful; do not overload the finance confirmation collection.
- Finance bot writes: **propose → Abi confirm** only. Bots cannot confirm. No pay / transfer / wire / trade via gateway.
- Axis key / vocabulary work: prefer **read-time** normalizers until an explicit history migration is approved. Do not rewrite live axis history without Abi OK and a backup/push in place.
